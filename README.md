# シンデレラの料理 — 最初の一皿

原作の最初のカレーを、二択の材料選びで遊ぶ静的なデモ。

## 起動

`python -m http.server 4173 --directory dist`

外部API・依存パッケージ・ビルドは不要。読み上げのみブラウザーの日本語音声を利用します。音声非対応でも文字で完結します。

## 体験

導入（料理上手なシンデレラと本を隠された事情を同じ画面で段階表示 → 姉の注文 → 助けるための材料選び）→ 3つの二択 → 調理 → 試食。正解ならおかわり、不正解なら別のおいしい料理になり作り直せます。

人物は三角の頭巾とエプロン姿のシンデレラに更新。導入の調理・本を持ち去る途中・本を隠した後・助けを求める場面と、姉の試食2表情を、構図を揃えた6コマの画像としてまとめています。食材6点・料理3点・ふた付き鍋は、絵本風に生成した独立の透過WebP画像。湯気は別レイヤー。人物の身体を分割しません。場面ごとに読み上げを停止し、モーダル・バックグラウンド移行でも音声をキャンセルします。調理は約5.4秒の4段階で進み、ふた付きの鍋で完成を伏せます。読み上げ中は次段階を待ち、設定・読み返し・非表示中は進行を止めます。完成後はユーザー操作で料理を公開します。待ち時間のスキップも可能です。すべての操作はネイティブボタンでタップ・キーボードに対応。動きを減らす設定・OSのreduced-motionを尊重します。

画像取得に失敗しても背景の代替表示と会話で進行可能。読み返しは会話と結果を静的に表示します。データの外部送信、ログイン、保存はありません。

## 確認

8通りの組み合わせの判定、ブラウザーで不正解 → 再挑戦 → 成功 → 終了、履歴、設定、最初から、390pxモバイルの横はみ出しを確認。

## 範囲

最初の一皿のみ。録音音声は未実装。原作の人物・物語はユーザーの作品。背景画・食材画・料理画はこのデモ用の生成素材。

## 画像素材

`dist/assets/` に個別の画像を配置。食材6点は3列×2行、料理と鍋4点は2列×2行で生成し、セル単位で切り出してWebPに変換しています。原画の背景透過を保持し、食材・料理・鍋の形や色をCSSで描いていません。画像取得に失敗しても食材名で選択でき、料理名でも進行できます。

## お姉さんの表情と食材配置

頭巾姿の共通シーン画像に、つんとした顔と試食時の2表情を収録。旧版の背景と透過表情は、新画像を取得できない場合の代替として保持しています。注文どおりのカレーでは満面の笑顔、別の料理では目を開けたままうれしそうな表情、注文・材料選び・調理ではつんとした顔です。選んだ食材はテーブルの固定3枠へ順番に置き、新しい1点だけに配置アニメーションをつけます。調理開始と選び直しで片づけます。

材料選びでは、原作に沿ってシンデレラの台詞と様子の描写を使い分け、人物の近くの吹き出しに表示します。同文を下の会話欄に重ねて見せず、スクリーンリーダーには一度だけ届けます。

## UIと原作の扱い

原作の台詞と地の文を区別します。豚肉／しらたきのペアでは「カレーといえば、しらたき、かしら？」というシンデレラの台詞、じゃがいも／たまごには追加のひと言なし、カレールー／ちくわぶではちくわぶをじっと見つめる様子を地の文として扱います。3組を出す順番と二択の左右は、挑戦ごとにランダム化します。設定や履歴を開いても提示順は変えません。料理判定は選んだ順に依存しません。

不要なセカンダリラベルや操作説明を避け、レイアウトで操作を伝えます。食材カードは絵と食材名だけにし、「これにする」や「食材の絵をタップして」の重複説明を置きません。絵の吹き出しと会話欄の同文は視覚的に重複させず、スクリーンリーダーには一度だけ届けます。

制作方針・原作資料・未決事項・次セッションへの案内は [HANDOFF.md](HANDOFF.md) を参照してください。

全編の構成と訂正事項は [制作範囲](docs/PRODUCTION_SCOPE.md)、導入の演出案は [導入案](docs/INTRO_STORYBOARD.md) を参照してください。導入は3画面構成です。最初の画面は調理→本を持ち去る途中→隠された後の差分を順に表示し、最初の文章を残して説明を追加します。「つづきを読む」を早く押すとその画面の残りを表示し、次に押すと注文へ進みます。設定・履歴・非表示中は進行を停止。動きを減らす設定では隠された後の絵と全文章を即時表示します。「頼んできます」に修正し、後からの自己紹介は省きました。

判定とシャッフルの検証：`node tests/rules.test.js`
