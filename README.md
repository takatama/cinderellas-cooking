# シンデレラの料理 — 最初の一皿

原作の最初のカレーを、二択の材料選びで遊ぶ静的なデモ。

## 起動

`python -m http.server 4173 --directory dist`

外部API・依存パッケージ・ビルドは不要。読み上げはブラウザーの日本語音声を使い、音なしでも文字で完結します。

## 導入

「料理が得意なシンデレラ。」→「しかし、おねえさんがいじわるをして、」→「大切な料理の本を隠してしまいました。」を、同じ欄へボタン操作で順に追加します。自動で次の絵や文章へは進みません。

姉の注文とシンデレラの台詞の後、原作と照合した「シンデレラのために、カレーの材料を選んであげますか？」を問いかけ、「はい」の返事で初めて材料選びへ。「いいえ」なら休止し、お願いへ戻れます。

## 絵と料理

三角の頭巾とエプロン姿のシンデレラが、自分の本を見ながら料理をします。背景は `dist/assets/kitchen-background.png` の1枚を固定し、人物・本・道具を含む透過の `intro-characters.png`（2列×3行）のみを切り替えます。背景と人物が同じ固定キャンバスを共有し、導入の文章が増えても背景の位置や倍率は変えません。背景込みの旧画像は記録として保持し、現在の画面では読み込みません。

材料は3組の順番と左右を挑戦ごとにランダム化。選んだ食材は固定3枠へ順に置き、判定は選択順に依存しません。注文通りならカレー、違えば別のおいしい料理になり再挑戦できます。

食材6点・料理3点・ふた付き鍋は独立した透過WebP画像。調理は約5.4秒の4段階で進み、完成料理を伏せた後、操作で公開します。調理中は読み上げやモーダルを待ち、スキップも可能です。姉はカレーで満面の笑顔、別の料理でも目を開けたまま喜びます。

## UIと確認

原作の台詞と地の文を区別し、追加の内容があるときだけ吹き出しを表示します。不要な補助ラベルや重複文を足しません。しらたきの台詞・ちくわぶの描写は、それぞれの食材ペアに紐付けています。

ネイティブボタンでタップ・キーボードに対応。動きを減らす設定でも、導入は同じ区切りで手動進行します。画像の読込失敗時にも文字で進行でき、履歴はメモリー内です。データ送信・ログイン・永続保存はありません。

`node tests/rules.test.js`

判定8通り×選択順6通り、提示順48通り、不正な食材を検証。ブラウザーで導入が待機中に進まないこと、クリックごとの文の追加、背景のsrcと表示領域の固定、協力の返事・再開、成功・再挑戦、履歴・設定・再スタート、画像失敗時の進行、320px／390pxとreduced-motionを確認しています。
