# 城・扉・魔法の部屋の画像（2026-11-01）

ユーザー添付の城の参考画像をもとに、石のアーチ・木の扉・金の曲線・青い旗・白い花の方向で制作。ユーザーの追加指示に従い、十字架を使わない。初期案の十字形の窓や宗教的に見える装飾は採用せず、葉・花・曲線へ修正した。外観の窓にも交差する桟を使わない。

採用する実装素材は `dist/assets/` の以下の四枚（各1536×1024）。人物・食材・完成皿は描き込んでいない。

- `castle-exterior.png`：城への誘い。
- `castle-door-closed.png`：閉じた扉。金の額の中は空白。
- `castle-door-open.png`：開いた扉と明るい廊下。閉扉と同じ構図。
- `magic-room.png`：魔法のオーブンと部屋。紙・材料・完成料理を描き込まない。

扉の文字は `doorInscription()` からDOMに載せ、問題文も同じ関数を使う。現行一周目の「おえかき」と判定は維持する。後の周回の別の文字・答えは今回実装しない。開扉後は札のDOMを隠す。数字盤の絵は追加せず、既存の四桁入力だけを使う。

オーブンの紙は独立したDOM。両方あり／一枚のみ／両方なしを保存された状態で切り替える。部屋内のphaseが変わっても背景を再生成せず、紙と調理中の淡い光だけを更新。画像失敗時も札・問題・フォーム・紙の選択を保持する。

背景と重ねる文字は `--scene-width` / `--scene-height` の3:2座標を共有。既存のノベルUI、人物・料理、謎の答え、保存キーとversionは保持。プリン・終幕の画像は未着手。

検証：構文、Node全3テスト、`castle-art.browser.cjs` の8画面（320〜1280px、1280×720／390×420を含む）で開閉・紙4状態・片方解決後の保存再開・完成前非表示・画像失敗時の解答継続が成功。既存 `journey.browser.cjs`（三幅）、`novel.browser.cjs`（三幅）、`cooking.browser.cjs`（七画面）も成功。PCの扉と部屋、320pxの扉、390×420の部屋を画像で確認。
