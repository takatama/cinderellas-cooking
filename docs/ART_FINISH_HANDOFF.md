## 最初に取り組む小さな単位（推奨順）

この順序は次の制作を始めやすくする提案であり、新しい人物像・構図を採用済みと扱わない。

1. **母親の一場面を具体化**：採用シンデレラと台所を固定し、母親の通常の依頼の構図を提示する。料理名のみの注文表示にし、テーブルに完成ハンバーグを描き込まない。確認後、材料選び・試食に使える差分を作る。
2. **母親の章を画像で通す**：新食材5種（じゃがいもは既存）と結果6料理を揃え、正解・別料理・再挑戦の絵の切り替えを確認する。
3. **王子の章**：王子の構図と、料理名＋閉じた銀皿の注文画面を確認し、新食材5種（たまごは既存）と結果7料理を揃える。
4. **城と謎**：城・扉・魔法の部屋・オーブン・独立した二枚の紙を揃える。扉や紙の文字は画面のテキストとして正確に重ねる。
5. **プリンと結末**：プリンの公開、王子の感動、会社設立とお取り寄せの後日談を仕上げる。
6. **全体を通して確認**：人物・背景・皿の目線・光・大きさを揃え、未置換の絵文字や紋章がないか点検する。

## 絵から答えを漏らさない

- お母さんの注文は料理名のみ。王子の注文は料理名＋中身の見えない銀皿。料理名を隠す合意ではない。
- 完成料理は公開操作の後に初めて見せる。バッジだけでなく、人物画像のテーブルや背景に焼き込まれた完成皿も注文時には表示しない。
- 選択済み食材は見せてよい。未選択の正解食材を、注文時のテーブルに並べてヒントにしない。
- オレンジの紙の問題を解く前に、答えのかぼちゃを部屋や紙に描いて示さない。ピンクの材料の答えも同様。
- 扉の札「おえかき」、問題「たさまとごう」などは生成画像の文字に頼らず、正しいDOM文字で載せる。答えの5467を扉の装飾に描かない。錠前を描いても編集できる入力は一つに保つ。
- 二枚の紙は別々に表示・非表示を切り替える。一枚解くとその紙だけが消え、両方を解いて初めてオーブンが使える。紙ごと焼き込まれた一枚絵だけで置換しない。

## 今のUIと配置を壊さないための実装上の要点

- 画像の枠、会話、操作、下部メニューを分けたノベル形式。ボタン位置が文章量で上下する旧UIへ戻さない。
- 通常会話は意味のまとまりで表示し、右下の「つづきへ」または会話欄タップ・Enter・Spaceで手動進行。二択・入力中は会話欄を押しても選択されない。
- 調理は約2.7秒の演出。途中の文ごとのクリックはない。演出終了後も料理を隠して待ち、公開操作で結果を出す。省略でき、設定・読み返し・別タブ中は停止する。
- 読み進める主操作は右下、選びなおし・演出省略は左下。返事・城への移動の二択は下端左の専用領域で、右下の連打が当たらない。
- **二択の左寄りは残っている**：ユーザーに理由を説明し、「下部中央で読み進めと高さを分ける方が自然」という案も返答したが、その配置は未実装・未採用。今回の依頼は画像仕上げの引き継ぎなので、中央配置への変更を合意済みと扱わない。
- 「上の選択肢から選んでください」「問題を見ながら答えてください」などの案内ラベル、ボタン末尾の矢印、右上メニューは不要。レイアウトで伝える。
- 地の文は話者名を繰り返さない。問いかけの後に「（シンデレラは、ちくわぶをじっと見つめています……）」を出す。母親の登場は「それを見ていたお母さん。」。失敗時の母親は「あら、これはハンバーグとは言えないわね。」。人物の口調を共用しない。
- `fitScene()`が背景の3:2の倍率と、狭幅の画像枠の高さを決める。狭い画面で画像の下に空欄を残さず、その高さを会話欄へ回す。顔・頭巾を切らない。
- **鍋・皿・食材は `#table-plane` 内**。`--scene-width`・`--scene-height`を使い、`#scene-canvas`と同じ大きさ・中央位置に揃えている。外側の`#art`の下端を基準に戻すと、画像下の空欄へ鍋が落ちる不具合が再発する。
- 採用画像は1536×1024の透過キャンバスが多い。新しい皿は余白・接地位置を既存画像に合わせるか、個別の配置値を明示して調整する。透過PNGのキャンバス全体と、絵が描かれた領域を混同しない。
- 文字・操作は人物の顔や完成皿に重ねない。回答時には問題文と入力欄を同時に確認できる構成を保つ。

保存は `cinderella-first-journey-v1`（version 1）、会話レイアウト識別は`readLayout:2`。材料、ペア順、紙の解決、回答入力、履歴などを保持する。画像の追加のために保存をリセットしたり、解く順番や料理判定を変えたりしない。

## 検証と公開

静的HTML/CSS/JSでビルド不要。ローカルサーバーとPlaywright・Chromiumが使える環境なら、例えば以下を実行する。環境のプレビュー手順・Sitesスキルを優先する。

node --check dist/game.js

# 別ターミナルから、変更に応じたブラウザー検証

CHROMIUM_PATH=/usr/bin/chromium node tests/journey.browser.cjs

直近の実装では全て成功している。画像追加後は特に、注文に完成皿が出ないこと、画像欠損時も進めること、各失敗料理、紙の両順序、設定・履歴・保存再開を確認する。320／390／690／760／1000／1280pxと高さの低い画面で、画像・鍋・食材・操作が重ならず、幅を戻しても位置が壊れないことを確認する。ソフトウェアキーボードは高さを縮めたChromiumでの検証までで、実機試験済みとは扱わない。

公開はその時点のSitesスキルを読む。`.openai/hosting.json`の同じproject_id、所有者のみの公開範囲を維持する。GitHubへコミット・pushし、同一の`dist/`を既存Sitesソースへpushして、そのコミットから作ったアーカイブで配信する。履歴を強制更新しない。この環境ではSites helperが見つからず、通常Gitと`git archive`で対応したが、次の環境ではhelperの有無を確認する。書込credentialは発行し直し、トークンを文書・ファイル・引数へ残さない。
