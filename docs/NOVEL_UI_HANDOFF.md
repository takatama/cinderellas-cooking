## 次にすること

絵本の見た目を残したノベルゲーム形式のUIを実装した。まず導入・材料の二択・扉の入力で操作位置を検証し、同じ枠組みを一周目の全場面へ適用する。一周目の判定・分岐・再挑戦・中断と再開は維持する。

ユーザーはノベルゲーム未経験。特定ジャンルの操作慣れを前提にせず、「つづきへ」「読み返す」「設定」など意味が分かる表示を使う。

## 変更する理由

ユーザーから「ボタンを押す位置が下や上に移動することがあるのが気になる」と指摘された。現在は文章量や選択肢・フォームの高さで操作位置が変わり、スマホではページのスクロールも必要になる。

改善の目標は次の三点。

1. 次に押す場所を毎回探さずに済む。
2. 読み進める連打で、材料や返事を誤って選ばない。
3. 謎に答えるとき、問題文を見失わない。

## レイアウトと操作

### 共通

- 絵の領域、会話欄、操作欄、下部メニューの位置を安定させる。絵を文章量で伸縮させない。
- 明るい生成りの不透明な会話欄、濃い茶の文字、落ち着いた緑の主ボタン。人物の顔や料理に本文をかぶせない。
- 通常の文字サイズではスクロールせず次の操作へ届く構成を目標にする。文字拡大・小さい画面では読めることを優先し、固定高さで文章を切り捨てない。
- 長文は意味のまとまりで区切る。台詞と地の文、協力を頼む問いかけを省略しない。
- 「つづきへ」は右下に固定する。文章や読み上げが終わっただけで次へ進めない。
- 選択肢・入力欄は予め確保した領域に出し、表示のたびに主操作を上下へ押し出さない。
- タップ対象は44×44 CSS px以上を目安にし、十分な間隔を確保する。
- 初回から矢印だけにせず「つづきへ」と表示。「バックログ」は「読み返す」という名前にする。
- 文字は待たずに読める表示を基本とする案。自動送りやスキップの常設など、未合意の機能を増やさない。

### 材料選び・はい／いいえ

- 「つづきへ」のあった場所に選択肢を重ねない。読む操作から選ぶ操作へ切り替わったことを配置で示す。
- 選択待ちでは汎用の読み進め操作を止める。会話欄や画面の余白をタップしても選択を確定しない。
- 食材は画像付きの二択を維持する。注文名と、既に選んだ材料も確認できるようにする。
- ペアの提示順・左右は挑戦開始時に固定する。画面更新・設定・履歴の開閉・再開で動かさない。
- 食材を選びなおす既存の導線を維持する。誤操作対策として、全ての二択に毎回確認ダイアログを足す必要はない。

### お城の扉・二色の紙

- 扉の問題文と入力欄を同時に確認できる専用画面にする。
- 「答える／数字を合わせる」と「ヒント」を同じ位置で使えるようにする。
- 画面案は扉の錠前と会話欄の入力に数字が二重に見える。実装では編集できる数字の入口を一つにし、扉の錠前を描く場合は装飾または入力値に連動する表示として扱う。
- スマホのソフトウェアキーボードが開いても、回答欄と送信ボタンへ到達できることを確認する。
- 入力中のEnterを「つづきへ」に流用しない。フォームの送信・数字や材料名の入力を壊さない。
- 誤答はその場で再入力できる。ヒントを読んでも進行や選択状況を失わない。

### 読み返す・保存

- 過去の文章は「読み返す」で確認できる。読み返しただけで食材・謎解きの状態を巻き戻さない。
- 短い会話単位に分割する場合、保存に表示中のページ位置も含める。既存の保存からも再開できるように移行または互換処理を考える。
- 設定・履歴・別タブ表示中は、読み上げと進行中の調理演出を停止する既存仕様を維持する。

以前の導入は、クリックごとに同じ欄へ文を追加する形で合意・実装していた。新UIで読める量に区切る際も内容を省略せず、変更の範囲を実画面で確認する。スクロールや位置移動が再発するなら、文の保持方法と会話欄の高さを合わせて見直す。

## 受け入れ確認

- PCとスマホ320px／390pxで、文章が短い場面と長い場面でも「つづきへ」の位置が変わらない。
- 自分のペースで読める。文章・読み上げの終了や画像読込では勝手に進まない。
- 読み進める連打が、次の「はい／いいえ」や材料選択まで確定しない。
- 右上ハンバーガーメニューがなく、「設定」の入口が下部に一つある。
- 注文時、人物絵・テーブル・料理バッジなど全てを含めて完成料理が表示されない。王子の料理は中身が見えない。
- 選択肢・入力欄が出ても本文・人物・料理を覆わず、本文も切れない。文字拡大でも読める。
- 扉・紙の問題文を見ながら回答できる。キーボード・Enter・タッチ・ソフトウェアキーボードで操作できる。
- 料理の判定24通り、再挑戦、紙を解く両順序、結末、履歴、中断／再開、画像失敗、破損セーブからの復帰が維持される。
- 実際の迷いにくさは、未経験のユーザーによる試遊で確認する。公式資料の調査だけで実証済みとは扱わない。
