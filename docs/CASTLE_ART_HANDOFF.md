## 次に作る画像と進め方

最初は**城へ向かう一場面の構図案**を提示して確認する。城の外観・廊下・人物をどこまで描くか、扉と部屋に何枚使うかは未採用。下記は作業順の提案であり、決定済みの構図や必要枚数ではない。

1. **城への移動**：王子とシンデレラの雰囲気につながる城の外観などを一案示す。既存の「お城へ行く／またあとで」の会話と手動操作を保つ。
2. **閉じた扉と開いた扉**：大きな扉、文字を載せる空の札、装飾の錠前。開扉後には見た目の変化をつける。入力は既存の四桁フォーム一つ。
3. **魔法の部屋とオーブン**：部屋の固定背景とオーブン、独立して消せる二色の紙を設計する。紙は両方あり／オレンジのみ／ピンクのみ／両方なしの4状態を再生成なしで表せる構成にする。
4. **調理中のオーブン**：紙がなくなってから使用可能。調理中の控えめな光などと、手動の完成公開をつなぐ。既存の通常調理の器具を重ねない。
5. **プリンと結末（次の単位）**：完成プリン、王子の感動、会社設立とお取り寄せの後日談。先に構図を確認してから進める。城の画像制作と一緒に無断で全素材を量産しない。

背景・扉・オーブン・紙・人物を何でも一枚に焼き込まない。文字と操作はDOMに残し、切替が必要な部品を分離する。既存の見た目と新しい画像の目線・光・色を揃える。

## 場面と状態の対応

正本は `dist/game.js` の `journeyContent()`・`isCastle()`・`updateJourneyArt()`。現在の `updateJourneyArt()` は次のように仮素材を共用している。

| phase | 現在の表示 | 画像化で確認すること |
| --- | --- | --- |
| `castle` | 城の紋章 | 城への誘い、休止と再開。直前の台所の完成皿を残さない |
| `door` | CSSの閉じた扉 | 「おえかき」の札、問題と四桁入力の同時表示、ヒントと誤答 |
| `door-open` | 同じCSS扉 | 現状は開扉専用の絵がない。開いた状態を新たに表現する |
| `room` / `orange` / `pink` | CSSオーブン＋未解決の紙 | 選んだ紙を読んでも他方の解決状態を維持する |
| `paper-solved` | 同じオーブン、解けた紙のみ非表示 | 一枚だけ消える。両方を解いた時だけ次の調理へ進む |
| `final-ready` | 紙なしのオーブン | 材料が物語で明示されてから。完成プリンはまだ見せない |
| `final-cooking` | オーブンが光る | 調理演出。通常の鍋を足さず、完成公開は手動で止める |
| `final-result` | オーブン＋仮のプリン | 公開後に初めて完成料理を表示。王子の願い、休止と再開 |
| `ending` / `complete` | 会社の紋章 | 後日談と完了。現状 `ending` ではプリンも表示、`complete` では非表示 |

`isCastle()` は城以降の各phaseをまとめた判定。台所の人物用 `showMother()`・`showPrince()` は城ではfalseになる。城で人物を出す場合は、採用された人物の再利用方法と背景の座標を設計してから実装する。既存の `showPrince()` の条件を広げるだけで全場面に台所を出さない。

`updateJourneyArt()` は `art.dataset.scene` が変わった時に骨格を作り、紙の表示は毎回 `state.orange` / `state.pink` で更新する。画像化後も同じ部屋内のphase変更・片方の解決・保存再開で見た目が更新されるようにする。`hold` は `returnPhase` に戻る。休止中も正答素材や完成料理を先に見せない。

## 謎と画像で守る条件

以下の答えは制作・検証用。未解決の画面に絵で描き込まない。

- 扉の札は「おえかき」。答えは **5467**。札・ヒント・入力は正確なDOM文字を使う。生成画像の装飾に5467を描かず、入力できそうな別の数字盤も増やさない。
- 最初のヒントは「青は十五」、続いてひらがなの順、最後に文字と数字の対応。画像でヒントの段階を先取りしない。
- オレンジの紙は「カンボジアから伝わった、カンボジアのような名前の野菜」。答えはかぼちゃ。**解く前の部屋・紙・オーブンにかぼちゃや完成プリンを描かない**。
- ピンクの紙は「たさまとごう」。答えはたまごと砂糖、順不同。文字はDOMに載せ、未解決時に材料の絵をヒントとして出さない。
- `dist/journey.js` の表記揺れ・全角数字・重複材料の判定は維持する。二周目の「パンのような名前」や「こんしそめお」を混ぜない。
- 二枚を解く順番は自由。一枚解いたらその紙だけを消し、両方を解いて初めて調理へ進める。再読み込みでも同じ状態へ戻す。
- `final-cooking` で完成プリンを先に見せず、「できた料理を見る」の後に初めて表示する。注文時に完成皿を隠す既存の方針も保持する。

## 固定する採用素材とUI

- シンデレラの基準は `dist/assets/help-characters.png`。結い髪、小さな生成りの三角の頭巾、青いリボン、普段着とエプロン。長髪やコック帽へ戻さない。同ファイルは姉も含むので、そのまま城へ貼らない。
- 王子は `prince.png` と `prince-delighted.png` / `prince-pleased.png` が採用済み。栗色の短髪、白と青の衣装、小さな王冠。顔だけのマスクで表情を重ね、髪・体・背景を表情ごとに生成し直さない。現在のマスクは元画像の中心64%／34%、半径8%／12%。
- 台所の背景・人物・食材16種・通常料理16皿・器具は作り直さない。料理と人物の位置は実ファイルとコードで確認する。
- 会話・絵・選択欄・右下の読み進め・下部メニューのノベル形式を保つ。文字やフォームを絵に焼き込まず、顔や完成皿にも重ねない。
- 通常会話は意味のまとまりで手動進行。会話欄タップ・Enter・Spaceは選択／入力待ちでは進めない。選択直後300msとダブルクリックのガードも維持する。
- `fitScene()` は3:2の絵と会話欄の最低高さから画面内の画像寸法を決める。画像化した城も狭幅で絵の下に空欄を作らず、低い画面で問題と入力を読める構成にする。
- **鍋・皿・選択済み食材は `#table-plane` 内**。背景と共通の `--scene-width` / `--scene-height` と中央座標を使う。外側の `#art` 下端を基準に戻さない。城の背景に机を描く場合は、プリンの接地位置も先に設計する。
- 保存キーは `cinderella-first-journey-v1`、version 1、`readLayout:2`。phase、会話位置、回答下書き、紙の解決、履歴などを維持。画像を増やすために保存をリセットしない。
- 画像が読めない時も問題文・入力・操作を残して進める。背景の読み込み失敗で扉や紙が操作不能にならないようにする。

## GitHubと公開時の注意

GitHub CLIの注入トークンはこの環境では期限切れになった。通常のfetchは使えたがpushは失敗したため、接続済みGitHubツールでblob→tree→commit→ref更新を実施。ローカルのtree SHAとの一致を確認し、旧HEADを指定したfast-forwardで同じブランチを更新した。認証切れをリポジトリ不存在と混同しない。資格情報を出力・文書化しない。

公開はその時点のSitesスキルを読み、`.openai/hosting.json` の同じproject_idを使う。短期credentialは再取得してstdinだけで渡す。前回はSites helperがなかったため、通常Gitで既存ソースを取得し、検証済みの `dist/` を同期、同じmainへpushし、そのHEADの `.openai/hosting.json` と `dist/` を `git archive` で梱包して所有者限定配信した。helperが提供される環境ではそちらを使う。成功した配信のIDと時刻、GitHubとSitesの `dist/` 一致を記録する。資料だけの変更では再配信しない。
