# 次の制作を進めるための構成

2026-11-01。一周目の完成版（GitHub main `2938784`、Site version 36）を基準に整理しました。導入・料理公開は手動、採用画像・表情マスク・配置・謎・台詞・保存キーは維持しています。

## 周回・英語版

原作表の9レシピ・72組合せを `content/catalog.json` に整理しました。一周目の3レシピのみ `playable`、二・三周目の6レシピは `source-only` です。判定は72通り×6順列の432ケースを元のCSVと照合しています。追加周回を選べる機能は今回追加していません。

食材と料理には `pork`、`curry` などのIDを付けました。表示名を変更してもIDでの判定は変わりません。レシピの `pairs` の各組から一点ずつ選び、各組の二番目を選んだかを3ビットにして `outcomes` の8通りへ対応させます。組の表示順・左右・選択順には依存しません。

原作資料に登場する全種類数と、このCSVに載る種類数には差があります。足りない料理を推測して登録せず、最終プリンとその材料を含む58個の食材・料理IDまでを今回の台帳にしています。

英語版は、素材名・料理名・組合せ・謎を原作と再照合して別の版として実装します。台帳の英語確認状態はすべて `unreviewed`。英語名や英語の調理文がないAPI呼出しはエラーにし、日本語へ暗黙に置き換えません。日本語の謎・手がかり・入力正規化・UI文言も、今後の英語版制作対象です。言語選択UIはまだありません。

## 保存データ

既存の `cinderella-first-journey-v1` をそのまま使います。シャッフル済み二択、選択済み食材、調理段階、読み位置、謎の入力下書きと履歴を保ちます。古い日本語名入り保存は互換入口で扱い、IDへの破壊的な一括移行はしていません。

壊れた入れ子や不正な料理結果は復元せず、新しく始められます。保存が禁止・容量超過の場合もゲームを続行します。二周目や別言語の保存が必要になったら、版を識別する新しいスキーマと明示的な移行処理を追加してください。

## 音声

読み上げ、BGM、SEは別チャンネルです。`audio-config.js` の `speech`、`music`、`effects` でファイルと音量を指定します。音源は追加していないためBGM・SEは無効で、従来の読み上げだけが既存ボタンで切り替わります。音源を採用する段階でBGM・SE用のユーザー操作による有効化UIも追加してください。

BGMは `music.tracks` へIDとパス、`music.scenes` へphaseとトラックIDを対応させます。SEは `effects.cues` に登録し、`audio.effect('choose')` などのイベントで呼びます。同じBGMは要素を再利用します。設定・履歴・タブ非表示で中断し、戻ったときにBGMだけ再開します。読み上げは古い台詞を再開せず、次の表示に合わせます。自動再生拒否や未対応音声で進行を止めません。音量・音色・端末ごとの聞きやすさは実際の音源を採用後に調整します。

## 画像配信

採用原画と旧素材67点は `artwork/originals/` に移動して保持しました。使用中の57点だけを `artwork/assets.json` で登録し、配信用WebPを生成します。元のWebPは再圧縮せずコピー。PNGは同じ寸法のロスレスWebPへ変換し、透明度・見える画素の一致を自動検証しています。人物のクロップ、髪型、顔マスクの座標は変えません。

背景5点には幅768pxの追加サイズを作り、`srcset` で選びます。透過人物・顔・箱などの合成レイヤーは同じ原画座標を保つため個別に縮小・トリミングしません。歴史用の旧画像10点は配信ディレクトリから外しました。

配信ファイル名に内容のSHA-256の先頭16桁を付けます。内容を変えるとURLが変わります。`_headers` は画像の長期immutableキャッシュ、HTML・JSの再検証を指定しています。ホストが `_headers` を扱う場合に適用され、Pythonの確認用サーバーはこのヘッダーを適用しません。今回は本番のキャッシュヘッダー実測まではしていません。

全食材・完成料理・器具の起動時先読みを廃止し、表示する選択肢・場面・調理段階に応じてロードします。完成料理の画像は手動公開後に取得します。画像失敗時の文章・旧人物コマ・紋章へのフォールバックは残しています。

画像は `dist/assets.js` で `idle` → `loading` → `ready` / `failed` を管理します。`ready` は通信完了だけでなく `decode()` 完了後です。描画側は生の `load` イベントではなく `assetready` / `asseterror` に応答します。読み込み中に代替の説明や人物ポーズを表示せず、失敗を確認したときだけフォールバックを表示してください。遅い応答が新しい場面へ戻らないことは `tests/scene-loading.browser.cjs` で確認します。

Chromium、DPR 1、キャッシュなし、ローカルHTTPで初回ロードの画像レスポンス本文を計測しました。圧縮・ネットワーク速度・本番CDNのキャッシュによって実際の待ち時間は変わります。

| 項目 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 初回の画像要求数 | 49件 | 2件 |
| 初回画像転送量：1280px | 60.30MB | 3.69MB |
| 初回画像転送量：390px | 60.30MB | 2.55MB |
| 使用中57点のフルサイズ合計 | 80.15MB | 57.34MB |

最後の行には小画面用の追加画像を含めていません。画像の再生成はPillowが必要です。

```sh
python3 -m pip install -r requirements-assets.txt
npm run build:assets
npm run check:assets
```

## 検証と配信

```sh
npm ci
npm run check
# 別ターミナルでサーバーを起動
python3 -m http.server 4173 --directory dist
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

`node scripts/test-browser.mjs delivery` のように名前の一部を指定すれば対象スイートだけ実行できます。全編・画像・描画・保存・ノベル操作に関わる変更では、関連する既存のブラウザーテストも通してください。

配信物は `.openai/hosting.json` と `dist/` だけをパッケージします。原画や制作資料はソースリポジトリに残し、公開ディレクトリへコピーしません。Site ID・所有者限定の公開範囲を維持し、検証済みコミットと一致する配信物を使います。問題があればSite version 36へ戻せます。
